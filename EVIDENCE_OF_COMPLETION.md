# 6. Evidence of Completion (Required)

Evidence should be clear, verifiable, and easy to review by the Ambassador Chapter Lead with minimal technical expertise.

**Note:** The repository remains **private**. All evidence will be submitted to and verified by the **assigned private reviewer** (e.g. access invite, shared materials, or handoff as agreed with the program).

**Deliverable 1**  

- **Evidence type:** Repo (private; access for assigned reviewer)  
- **Description:** Private repository. Access will be granted to the assigned private reviewer so they can browse or clone the ArcusX codebase (frontend and backend) and verify the project exists, its structure, and that it is built on Stellar (Trustless Work, USDC, Freighter).

**Deliverable 2**  

- **Evidence type:** Doc (guide of changes made)  
- **Description:** Guide of changes made provided to the reviewer: a single document listing what was implemented (e.g. security fixes, API/CORS/JWT, light theme, responsiveness, i18n, additional wallet, documentation). Lets the reviewer verify scope and completion without reading the full codebase.

**Deliverable 3**  

- **Evidence type:** Demo (video or script showing the changes)  
- **Description:** Demo shared with the reviewer that shows the changes made: a video (private or unlisted link) or a written script demonstrating the implemented updates (e.g. flow, UI, theme, wallet). Lets the reviewer see what was delivered.
